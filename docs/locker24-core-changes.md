# Locker24 changes to Headwind core files

Our code lives in `com.hmdm.launcher.locker24` and `app/src/locker24/`. This page lists every change to a file that comes from upstream (Headwind MDM launcher 6.40, base `75eff13` on `master`), so an upstream merge can be reviewed file by file.

The fork is ours. Upstream bugs are fixed in core files even when the fix changes the `opensource` flavor too; those fixes are marked **both flavors** below.

| File | Change | Why | Flavors |
|---|---|---|---|
| `.gitignore` | Ignores `/locker24.properties` and `*.jks`. | The signing config and keystore stay out of git. | both |
| `app/build.gradle` | `locker24` product flavor: package `app.locker24.mdm`, server URLs, MQTT port, version, release signing from `locker24.properties` (the build fails without it). | Own package, server and signing. | locker24 |
| `locker24.properties.example` | Template for the signing properties. | Documents the required keys without secrets. | locker24 |
| `pro/ProUtils.java` | Lock-task kiosk (`startCosuKioskMode`, kiosk options, unlock), configured orientation (`applyConfiguredOrientation`), kiosk app update handling (forced fresh start, 3 s retry, settled check, joining a fresh start still coming up). Delegates decisions to `locker24/KioskPolicy`, `KioskStartPolicy`, `OrientationPolicy`. | ProUtils is the upstream extension point for the kiosk. | locker24 (most methods check the flavor) |
| `util/Utils.java` | `orientationDiag()` and an orientation log line in `setOrientation`. | Remote diagnosis of orientation problems. | both (logging only) |
| `ui/MainActivity.java` `onCreate` | Requests the configured orientation; logs the requested orientation. | The kiosk app came up in the wrong orientation after updates. | locker24 (`applyConfiguredOrientation` is a no-op in opensource) |
| `ui/MainActivity.java` `lockOrientation` | Uses the configured orientation when there is one instead of locking the current one. | Same. | locker24 |
| `ui/MainActivity.java` `onCreate`, Initializer completion | Returns when the instance is already destroyed. | Initialization finishes asynchronously; a recreated instance registered its receivers after `onDestroy`, never unregistered them, and ran a second config update on every push. | **both flavors** |
| `ui/MainActivity.java` UINotifier callbacks | On a destroyed instance: no error dialogs (download/install errors take the non-interactive skip/repeat path), `onConfigUpdateComplete` and `onAllAppInstallComplete` are handed to the current instance (`liveInstance()`). | A flow started by a destroyed instance must not show dialogs or start the kiosk from the dead instance. | **both flavors** |
| `helper/ConfigUpdater.java` | `updateConfig` passes `locker24/ConfigFlows` (process-wide `ConfigFlowGate`) before `runConfigUpdate`; internal retries (network retry, server migration) call `runConfigUpdate`; `skipConfigLoad` passes the gate; the flow ends the gate on completion, server error, final network error and load-only finish; a superseded flow stops before applying the configuration, updating files and updating applications. | Each ConfigUpdater guarded only itself, so two flows ran side by side and downloaded and installed the same APK twice (ENOENT on the second install). One flow runs at a time; requests made meanwhile run once more afterwards; a flow running for 10 min or owned by a destroyed launcher instance is taken over. | **both flavors** |
| `worker/RemoteLogWorker.java` | `doWork` drains through `locker24/LogDrain`: one drain at a time (a second worker returns at once), a failed delete ends the drain, and rows written after the last empty select schedule another upload. | `scheduleUpload` uses `REPLACE` and `MainActivity.startServices` resets the scheduled flag on every resume; a replaced worker keeps running, so two workers uploaded the same rows (2-3 copies on the server). A blocking lock would tie up WorkManager threads. | **both flavors** |
| `db/LogTable.java` | `delete` returns whether the transaction succeeded; `deleteOldItems` uses `DELETE_OLD_LOGS`. | The drain must stop when uploaded rows cannot be deleted. Old logs were never purged because the purge ran the delete-by-id statement with a timestamp. | **both flavors** |
